# Соответствие домена и СМО варианта №26

| Элемент СМО | Сущность домена | Представление в модели |
| --- | --- | --- |
| Источник ИБ, ИЗ2 | Игровой клиент | `Source`. Генерирует запросы через интервалы τ = a + (b − a) × U, где U ∈ [0, 1), 0 < a < b. |
| Заявка | Запрос на одно игровое действие | `Request`. Идентификатор, источник, тип действия, модельные метки и номер постановки. |
| Общий буфер | Массив ожидающих действий | `Buffer`. N ячеек, счётчик постановок и УБ для Д2Б3. Ячейки сохраняют номера при записи и извлечении. |
| Диспетчер постановки | Компонент приёма запросов | `PlacementDispatcher`. Выбирает первую свободную ячейку по Д1ОЗ3, при переполнении применяет Д1ОО4. |
| Отказ Д1ОО4 | Потеря ожидающего действия | Из заполненного буфера выходит запрос с максимальным номером постановки среди ожидающих. Потеря учитывается у его источника. |
| Диспетчер выбора | Планировщик игровой обработки | `SelectionDispatcher`. Ищет прибор от УП по Д2П2 и заявку от УБ по Д2Б3. |
| Прибор ПЗ1 | Серверный обработчик игровой логики | `Device`. На один запрос выбирает длительность t = −ln(U) / μ, где U ∈ (0, 1), μ > 0. |
| Успешный выход | Результат обработки действия | Заявка покидает прибор по событию завершения обслуживания. |
| Модельное время и календарь | Порядок симулируемых поступлений и завершений | `Simulator`, `EventCalendar`, `Event`. Определяют следующее событие и порядок обработки совпадений. |
| Сбор статистики | Учёт потерь, задержек и загрузки | `StatisticsCollector`. Ведёт счётчики, накапливает времена и их квадраты. |
| ОД2 | Пошаговое наблюдение за сервером | `StepView`. Формализованная схема, календарь, текущие показатели и оба указателя. |
| ОР1 | Сводка по прогону | `AutoReportView`. Таблицы по клиентам и обработчикам. |
