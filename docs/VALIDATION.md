# Аудит первичных артефактов

**Жирнов М. С., группа 5130904/40101. Вариант №26, обработка телеметрии датчиков промышленного оборудования.**

## Источники и расхождения

- В приложении 1 файла «СМО_пособие_2025» строка №26 содержит `ИБ | ИЗ2 | ПЗ1 | Д10З3 | Д10О4 | Д2П2 | Д2Б3 | ОР1 | ОД2`. Толкования сверены с приложением 3. В проекте в двух кодах буфера использована кириллическая О вместо 0. Содержание бизнес-домена и всех девяти строк маппинга сверено с предоставленными DOCX после переноса.
- Бизнес-домен задаёт равномерный закон на `[a, b]`, а ТЗ указывает способ получения интервала с `U ∈ [0, 1)`. В непрерывном распределении отдельная граница имеет нулевую вероятность. В описании домена сохранена исходная формулировка, в архитектуре зафиксирован способ выборки из ТЗ.
- Пособие связывает выбивание с полным буфером и занятыми приборами. ТЗ задаёт безусловную активацию планировщика после каждого прихода и завершения. В результате между событиями полный буфер означает, что свободных приборов нет. Это позволяет приёмщику применять отказ, используя только состояние буфера.
- В пособии временная диаграмма включена в общий перечень первого этапа. Памятка преподавателя и ТЗ снимают требование её визуализировать. Подготовлены sequence-диаграммы UML и формализованная схема ОД2. Таблица календаря и журнал переходов добавлены к состоянию ОД2 по памятке.
- Общие указания пособия упоминают графики. Строка №26 задаёт ОР1, а памятка требует графики автоматического режима для вариантов с соответствующим кодом. По №26 спроектированы две таблицы. Памятка относит сравнение конфигураций и экономическое обоснование к итоговому отчёту после вычислительных экспериментов. Здесь зафиксированы структуры для следующего этапа.
- Предыдущий проект содержал формулу №26, но описывал другую предметную область и ограничивал одну активацию планировщика одной передачей. Рабочие документы и изображения заменены, история исходного проекта сохранена. [m1shanyanba/aps](https://github.com/m1shanyanba/aps/tree/41f02fcf280d5ebf1d656673ecf37eb13dcd23ed)
- Из репозитория с вариантом №15 взята идея навигации по Markdown и пар «исходник PlantUML + PNG». В этом примере для обслуживания указан ПЗ2, тогда как строка №15 приложенного пособия содержит ПЗ1. Для проверки нашего проекта использована только строка №26 и расшифровка её кодов. [mokkenz1/smo-online-game-service](https://github.com/mokkenz1/smo-online-game-service/tree/aea4684ddc3b9552b56e0389c39b1c422b3a4d98)
- Приложенный пример sequence использован для оформления вызовов, ответов и условных блоков. Порядок обработки совпадающих событий, лимит генераций на весь прогон и момент первой генерации описаны как проектные решения в [архитектуре](architecture-decisions.md).

| Проверка | Результат |
