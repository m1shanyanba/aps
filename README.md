# Обработка телеметрии датчиков промышленного оборудования

Учебное приложение для имитационного моделирования системы массового обслуживания и первичные проектные артефакты. **Вариант №26.** Студент **Жирнов М. С.**, группа **5130904/40101**.

`ИБ — ИЗ2 — ПЗ1 — Д1ОЗ3 — Д1ОО4 — Д2П2 — Д2Б3 — ОР1 — ОД2`

| Код | Дисциплина |
| --- | --- |
| ИБ | Каждый датчик независимо формирует бесконечный поток. |
| ИЗ2 | Интервалы между генерациями имеют равномерное распределение. |
| ПЗ1 | Длительности обслуживания имеют экспоненциальное распределение. |
| Д1ОЗ3 | Новое сообщение ставится в первую свободную ячейку при просмотре с начала. |
| Д1ОО4 | При полном буфере выбивается последняя поставленная из ожидающих заявок. Новая занимает её ячейку. |
| Д2П2 | Первый свободный прибор выбирается по кольцу от УП. |
| Д2Б3 | Первая занятая ячейка выбирается по кольцу от УБ. |
| ОР1 | Две сводные таблицы автоматического режима, по датчикам и приборам. |
| ОД2 | Формализованная схема и состояние СМО после каждого события. |

Датчики передают температуру, давление и вибрацию. Сервер помещает все сообщения в общий буфер. Планировщик запускается после постановки сообщения или освобождения узла, сначала ищет свободный прибор, затем ожидающее измерение и продолжает передачи, пока находит пары. Узел моделирует проверку, преобразование и сохранение измерения. При переполнении потеря учитывается у датчика, создавшего вытесненное сообщение. Календарь управляет переходами модельного времени. После последней генерации СМО завершает оставшееся обслуживание.

## Установка и запуск

Понадобятся Python 3.10 или новее и Tkinter. Сторонние Python-пакеты не нужны. На Windows и macOS можно установить Python с [python.org](https://www.python.org/downloads/). На Debian и Ubuntu установите системный пакет командой `sudo apt install python3-tk`.

Откройте терминал в корне проекта. На macOS и Linux используйте `python3`, если команда `python` отсутствует. На Windows можно использовать `py -3`.

```bash
python -m tkinter
python main.py
python -m unittest discover -s tests
```

Первая команда открывает тестовое окно Tk. Для двух тестов интерфейса нужен доступный графический дисплей. Тесты модели и экспериментов запускаются и без него. Java и Graphviz нужны только для повторной генерации приложенных диаграмм.

## Режимы приложения

| Вкладка | Что можно сделать |
| --- | --- |
| Настройки | Задать число датчиков, узлов и ячеек, диапазон интервалов, интенсивность, лимит и seed. Выбрать один из трёх режимов нагрузки. |
| Пошаговый режим · ОД2 | Просматривать схему, календарь, журнал, состояния и кольцевые указатели. Шаг обрабатывает одно событие. Кнопка «Ручной сценарий» воспроизводит восемь заявок из документации. |
| Автоматический режим · ОР1 | Выполнить полный прогон по лимиту или подобрать объём по оценке вероятности отказа. Сводные таблицы и история итераций открываются на отдельных вкладках. |
| Исследование конфигураций | Задать сетку, например `4:6:1`, условия и условные цены. Сравнить таблицу, оценку стоимости, CSV и график по одному параметру. |

Экран показывает время в условных единицах. Значения измерений и цены демонстрационные. Подбор объёма использует приближённый критерий пособия для общей доли отказов. Гарантии точности временных характеристик из него не следуют.

## Генерация PNG

Изображения подготовлены в PlantUML 1.2025.10. Для повторной генерации понадобятся Java, Graphviz (`dot`) и шрифт DejaVu Sans. Из корня репозитория запустите команды, подставив путь к JAR.

```bash
plantuml_jar=/path/to/plantuml.jar
java -Djava.awt.headless=true -jar "$plantuml_jar" \
  -charset UTF-8 -failfast2 -checkonly docs/artifacts/*.puml
java -Djava.awt.headless=true -DPLANTUML_LIMIT_SIZE=8192 -jar "$plantuml_jar" \
  -charset UTF-8 -failfast2 -tpng docs/artifacts/*.puml
```

Для крупной схемы можно сгенерировать масштабируемое изображение той же командой с `-tsvg` вместо `-tpng`.
