# Сервис обработки действий игроков на сервере онлайн-игры

Первичные проектные артефакты курсовой работы по моделированию СМО. Вариант №26.

`ИБ — ИЗ2 — ПЗ1 — Д1ОЗ3 — Д1ОО4 — Д2П2 — Д2Б3 — ОР1 — ОД2`

| Код | Дисциплина | Правило модели |
| --- | --- | --- |
| ИБ | Бесконечные источники заявок | Каждый из K игровых клиентов может генерировать произвольное число запросов. |
| ИЗ2 | Равномерные интервалы генерации | τ = a + (b − a) × U, где U ∈ [0, 1), 0 < a < b. |
| ПЗ1 | Экспоненциальное время обслуживания | t = −ln(U) / μ, где U ∈ (0, 1), μ > 0. |
| Д1ОЗ3 | Постановка на первое свободное место | Просмотр ячеек с первой до первой пустой. Ячейки сохраняют номера. |
| Д1ОО4 | Отказ последней поставленной в буфер заявке | Извлечь ожидающую заявку с максимальным номером постановки. Новая занимает её ячейку. |
| Д2П2 | Кольцевой выбор прибора | Искать первый свободный прибор от УП, при занятости пропускать прибор. |
| Д2Б3 | Кольцевой выбор заявки | Искать первую занятую ячейку от УБ, пропуская пустые. |
| ОР1 | Сводная таблица результатов | Показатели по каждому источнику и каждому прибору. |
| ОД2 | Формализованная схема и текущее состояние | Снимок схемы и таблица календаря после каждого обработанного события. |

## Как работает модель

Игровые клиенты отправляют запросы на перемещение, атаку и другие действия. Диспетчер постановки записывает каждый запрос в общий буфер на N мест. Диспетчер выбора получает одну попытку назначить заявку после постановки или освобождения прибора. Он проверяет наличие свободного обработчика, затем извлекает заявку и передаёт её на обслуживание. Каждый из M обработчиков принимает одно действие за раз и поддерживает все типы действий.

УП и УБ — независимые указатели. Каждый начинается с позиции 1 и продвигается после успешного назначения на позицию, следующую за выбранным прибором или ячейкой. Если пары «свободный прибор и заявка» нет, указатели сохраняют положение. Календарь определяет следующий момент генерации или окончания обслуживания, а диспетчеры выполняют соответствующие переходы в том же модельном времени.

Для ОР1 предусмотрены числа генераций, отказов и завершений, вероятность отказа по источникам, средние времена ожидания, обслуживания и пребывания, дисперсии ожидания и обслуживания, коэффициенты использования приборов. Для ОД2 предусмотрены значения УП и УБ, состояние источников, буфера и приборов, последнее событие и текущие показатели, включая долю отказов.

## Генерация PNG

Понадобятся Java, JAR PlantUML 1.2025.4 и системный шрифт с кириллицей. Из корня проекта подставьте путь к JAR и выполните команды. Диаграмма классов и формализованная схема используют встроенный компоновщик Smetana.

```bash
java -Djava.awt.headless=true -jar /path/to/plantuml.jar \
  -charset UTF-8 -failfast2 -checkonly docs/artifacts/*.puml
java -Djava.awt.headless=true -DPLANTUML_LIMIT_SIZE=8192 -jar /path/to/plantuml.jar \
  -charset UTF-8 -failfast2 -tpng docs/artifacts/*.puml
```

Указания к варианту сверены с памяткой преподавателя и методическим пособием, включая таблицу вариантов и приложение о дисциплинах и отображении. [Репозиторий варианта №15](https://github.com/mokkenz1/smo-online-game-service) использован как образец структуры документов и диаграмм. [Справка PlantUML по командной строке](https://plantuml.com/command-line).
